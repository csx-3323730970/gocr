# ADR-0004：规则分层采用追加，而不是高层替换低层

## 背景

规则分四层：default → language → project → CLI。真实评审工具里常见一个坑：用户写了一条 catch-all 项目规则，结果把语言规则整段替换掉了，导致 Go 并发规则全部失效，评审质量悄然下降。

## 候选方案

1. 高层替换低层：语义简单，但容易误伤，且失效是静默的。
2. 高层追加到低层之后：提示词变长，但规则永远叠加，行为可预测。
3. 每条规则带 replace/merge 开关：最灵活，也最容易配置出事故。

## 决定

选 2。所有匹配的层按顺序拼接到 system 之外的 user prompt，带标题分隔。规则文档本身短（几十行），token 成本可接受；项目规则无法意外覆盖语言规则。

## 后果

- 正收益：可预测、无静默失效；项目可以放心写 catch-all 规则。
- 成本：提示词更长；重复规则需要人工去重（当前由 `uniqueStrings` 合并 bundle 内的规则文档）。
- 约束：如果未来出现规则冲突，应通过更具体的 glob 选择层，而不是引入替换语义。
