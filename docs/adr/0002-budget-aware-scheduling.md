# ADR-0002：预算感知调度（令牌桶 + token 预算 + 背压）

## 背景

评审任务由 LLM 驱动，单次成本与延迟都高，且 provider 有 RPM/TPM 限制。无脑并发大 changeset 会同时打爆供应商限流和服务自身内存；只看并发数不看成本，会让一次评审烧掉一天的预算。

## 候选方案

1. 直接 `errgroup.SetLimit(N)`，失败重试。
2. 串行执行，保证不打爆但吞吐低。
3. 有界队列 + worker 池 + provider 维度令牌桶（RPM/TPM）+ 全局 token 预算 + 满载背压；预算接近耗尽时降级（减少 tool 轮次、跳过低优先级 bundle）。

## 决定

选 3。调度层位于 `internal/job`：入口队列有界，满了返回 429 + Retry-After；每个 provider 有令牌桶；每次评审带预算，超预算按降级策略收敛。LLM 调用不放在数据库事务里。

## 后果

- 正收益：过载时行为可预期（拒绝而不是雪崩）；成本可控；指标可观测（队列深度、in-flight、重试率、tokens/评审）。
- 成本：调度逻辑比 errgroup 复杂，需要压测与故障注入验证。
- 约束：失败策略要显式（单元失败降级继续 vs 整体取消），并写进 ADR；评测必须固定预算口径才能横向对比。
