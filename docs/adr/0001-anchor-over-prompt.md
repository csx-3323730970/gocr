# ADR-0001：用代码做行号锚定，而不是靠 prompt 求模型给准行号

## 背景

AI 评审最有价值的输出必须落在 diff 的某一行上，才能 inline 展示、才能被人信任。实测中模型给出的行号经常偏移，甚至指向不存在或已删除的行。仅靠 prompt 强调「请给准确行号」无法稳定解决。

## 候选方案

1. 强化 prompt，要求模型输出行号与代码片段。
2. 模型给出行号 + 代码片段，由 Go 代码在 diff 行号空间内校验、模糊匹配与纠偏。
3. 放弃行级，统一降级为文件级评论。

## 决定

选 2。锚定是独立模块 `internal/anchor`，按 exact → fuzzy（窗口内归一化相似度）→ 全文 hunt → downgrade → drop 的顺序处理，并为每条结果输出 `confidence` 与 `method`。锚不上时显式标注「未能定位到具体行」，绝不静默透传。

## 后果

- 正收益：行号可靠性从「模型自觉」变成「可校验的确定性流程」，评测可单独统计 anchor accuracy。
- 成本：需要先实现精确的 diff 行号空间（`source.FileDiff`），并维护 20+ 个「模型报错位置」的回归 case。
- 约束：只解析 `git diff` unified 格式，不自研 Myers diff。
